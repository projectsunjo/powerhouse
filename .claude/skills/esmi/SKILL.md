# ESMI (Energy Solution Market Info)

매일 아침 에너지/반도체/데이터센터 시장 동향을 검색해 정리하는 데일리 브리핑 스킬.

## 트리거

다음과 같은 **짧은 메시지**를 받으면, 별도의 설명이나 확인 질문 없이 곧바로 이 스킬을 실행한다:
- "브리핑", "전력 브리핑", "ESMI", "오늘 브리핑", "오늘 동향" 등

트리거 메시지 자체에는 부연 설명을 붙이지 않고, 바로 검색 → 요약 → HTML 출력으로 넘어간다.

## 검색 기준 시간 (중요)

- 기본 원칙: **최근 24시간 이내** 뉴스만 다룬다.
- **예외**: 실행 시점(오늘)이 **월요일**이면, 주말 동안 쌓인 뉴스를 놓치지 않도록 **24시간×3 = 72시간 이내**로 기준을 넓힌다.
- 이 판단은 매번 실행 시점의 실제 요일을 확인해서 적용한다 (예: 화~일요일 실행 → 24시간, 월요일 실행 → 72시간).
- 사용자가 채팅으로 별도 기간(예: "8/28~31로 검색해줘")을 직접 지정하면, 위 기본 원칙 대신 그 지정된 기간을 그대로 따른다.
- 이 기준은 아래 7개 항목 전체와, "국내 반도체 관련 전력/발전 업체"의 하위 그룹에도 동일하게 적용된다.

**국내 반도체 관련 전력/발전 업체 및 관련 뉴스, 동향**

- **평택** (삼성전자 평택캠퍼스 P1~P6 등): 팹 증설에 따른 전력·용수 공급 이슈, 변전소·송전선로 신증설, 협력사·산업생태계 집적 이슈, 지자체(평택시)·주민 관련 갈등이나 지원 정책
- **호남권** (삼성전자·SK하이닉스 반도체 산단): 전력 수요(GW), 원전/재생에너지/LNG 조합, 송전선로 신설, 전기요금 정책뿐 아니라 **노사 갈등(노조 반대, 경총 입장 등), 지역 재정, 정책 리스크도 포함**

- 검색어 예시: "용인 반도체 클러스터 전력", "평택 삼성전자 전력", "평택캠퍼스 송전선로", "호남 반도체 산단 전력", "용인 반도체 클러스터 노조", "호남 반도체 세수", "반도체 대미투자 압박"

- **비교 인사이트 작성 규칙**: 매 실행 시, 그날 수집된 뉴스를 바탕으로 SOFC 대비 이들 대안 발전원의 상대적 강약점(리드타임, 단가/kW, 효율, 배출, 설치 용이성, 유지보수, 확장성 등)을 3~5줄로 요약한다. 확정된 사실 기반으로 작성하고, 없는 수치를 지어내지 않는다.

## 검색 깊이 규칙 (중요 — 결과물의 정보 밀도를 좌우함)

뉴스가 있는 항목이라도 검색을 1~2번만 하고 끝내지 않는다. 아래를 **매 항목 기본 동작**으로 삼는다 (뉴스가 없을 때만 확장하는 게 아니라, 뉴스를 찾은 뒤에도 더 깊이 판다):

- **항목당 최소 2~4회** 이상 서로 다른 키워드로 검색한다. 첫 검색에서 관련 기사가 나왔어도, 구체적 수치·기업명·계약조건이 아직 부족하면 검색을 이어간다 (예: 회사명 직접 검색, 관련 인물/기관명 검색, 영문 검색 병행).
- **구체적 수치를 끝까지 찾는다**: 계약 금액($/원), 용량(MW/GW), 지분율, 기간, 금리/스프레드(bp), 주가 변동률, 순위·점유율, 캐파(생산능력) 등. "수백억 원대", "대규모"처럼 뭉뚱그리지 않고 실제 숫자를 찾을 때까지 검색어를 바꿔가며 재시도한다.
- **한 항목에 가능하면 2개 이상의 출처를 인용한다.** 같은 사건을 다룬 여러 매체 기사가 있으면 서로 다른 세부사항(예: 규모는 A매체, 후속 반응은 B매체)을 조합해 요약을 더 두텁게 만든다. 다만 저작권 규칙(직접 인용 15단어 미만, 출처당 1회)은 그대로 지킨다.
- 워치리스트에 있는 기업이 뉴스에 등장하면, 그 기업명 자체로 한 번 더 검색해서 실적발표·소송·계약·주가 반응 등 파생 정보가 있는지 확인한다.
- 이 규칙은 "항목 정렬 규칙"이나 "날짜 표기 규칙"보다 먼저 적용된다 — 즉, 얕은 요약을 빨리 만드는 것보다 깊이 있는 요약을 만드는 것을 우선한다. 다만 "검색 기준 시간" 범위(평일 24시간/월요일 72시간)를 벗어난 오래된 뉴스를 끌어오는 것은 여전히 금지한다.

## 사용자가 특정 기사 URL을 제공한 경우

사용자가 특정 뉴스 URL(들)을 직접 붙여넣으며 "이것도 포함해줘" 등으로 요청하면:
1. `web_fetch`로 각 URL의 실제 본문을 확인한다 (제목만 보고 넘겨짚지 않는다).
2. 내용을 위 7개 항목 중 가장 적합한 항목(하위 그룹 포함)에 배치한다. 언뜻 "전력/발전"과 무관해 보여도(예: 노동쟁의, 세수 갈등, 통상 압박) 반도체 클러스터 조성에 실질적 영향을 미치는 내용이면 "국내 반도체 관련 전력/발전 업체" 항목(해당 하위 그룹: 용인/평택/호남권/기타)에 포함한다. 특정 산단과 무관한 일반 발전·송전·전력정책 뉴스라면 "국내 발전사(공기업·민간) 동향" 항목에 배치한다.
3. 자체 검색으로 찾은 뉴스와 동일한 형식(요약+배지+시사점+출처 링크)으로 정리한다.

## 항목 정렬 규칙 (중요 — 매 실행 시 반드시 적용)

- 최종 HTML에서 항목에는 **번호를 매기지 않는다** (①②③... 원문자 사용 금지). 굵은 제목 텍스트만 사용한다.
- 항목 순서는 고정하지 않고, **매 실행마다 아래 기준으로 동적 재배열**한다:
  1. 그 회차에 **실제 뉴스 내용이 있는 항목**을 모두 위쪽으로 모은다.
  2. **"특이사항 없음"으로 끝나는 항목**은 모두 아래쪽으로 내린다.
  3. 각 그룹(내용 있음 / 특이사항 없음) 내부에서는 원래 기본 순서를 그대로 유지한다: SOFC·PAFC 업체 동향 → SOFC 규제 → 국내 반도체 전력/발전 업체 → 국내 발전사 동향 → 데이터센터 → 금융조달 → Time-to-Power 비교.
- "국내 반도체 관련 전력/발전 업체" 항목의 **하위 그룹(용인/평택/호남권/기타)도 동일한 원칙**으로 정렬한다: 내용이 있는 하위 그룹을 위로, "특이사항 없음"인 하위 그룹을 아래로 (하위 그룹 간 기본 순서는 용인→평택→호남권→기타).

## 날짜 표기 규칙 (중요)

- 본문·배지 어디에도 **"오늘", "어제", "이번주" 같은 상대적 시간 표현을 쓰지 않는다.** 항상 **구체적인 날짜(M/D 형식, 예: "9/2", "9/1")**로 명시한다.
- 예: "오늘(9/2) 발표했다" (X) → "9월 2일 발표했다" (O). 배지에도 "오늘" 대신 "9/2"처럼 실제 날짜를 적는다.
- **7개 항목 전체(예외 없이 금융조달·Time-to-Power 포함)에서, 뉴스가 있는 모든 항목은 다른 항목들과 동일하게 날짜 배지를 반드시 포함한다.** 특정 항목만 날짜 배지를 빠뜨리는 일이 없도록, 최종 HTML을 작성한 뒤 모든 "뉴스 있음" 항목에 날짜 배지가 실제로 들어갔는지 한 번 더 확인한다.
- 헤더의 "조사 날짜"는 예외적으로 전체 날짜(YYYY년 M월 D일)로 표기하되, 이 역시 "오늘"이라는 단어 없이 날짜 자체만 쓴다.

## 요약 작성 규칙

- 검색 기준: 위 "검색 기준 시간" 규칙(평일 24시간 / 월요일 72시간, 또는 사용자 지정 기간)에 맞는 뉴스 우선.
- **카테고리별 연관 주제 확장 규칙 (중요 — 반드시 여러 단계로 시도)**: 시간 기준 내에 뉴스가 없다고 해서 1~2번 검색해보고 곧바로 "특이사항 없음"으로 넘기지 않는다. 단, **시간 기준 자체를 넓히지는 않는다** — 어디까지나 "검색 기준 시간" 내에서만 찾는다. 대신 아래처럼 **검색 주제/키워드를 단계적으로 넓혀가며 최소 2~3차례 재시도**한다:
  1. 1차: 항목의 핵심 키워드로 직접 검색 (예: "SOFC 규제")
  2. 2차: 상위/인접 개념으로 확장 (예: "수소법", "청정에너지 정책", "전력시장 제도 개편")
  3. 3차: 그 항목이 속한 더 큰 산업/정책 카테고리로 확장 (예: SOFC 규제 → "발전 관련 국회 입법", "에너지 정책 뉴스"; 반도체 전력 하위그룹인 "기타" → "국내 반도체 산업 정책 뉴스", "반도체특별법 후속"; Time-to-Power → "가스터빈 업계 뉴스", "발전기 제조사 뉴스" 등)
  같은 시간창 안에서 이렇게 범위를 넓혀도 정말 관련 뉴스가 전혀 없을 때만 "특이사항 없음"으로 처리한다. 몇 주~몇 달 전의 오래된 뉴스를 시간 기준 밖에서 끌어오는 것은 여전히 금지한다.
- 주제를 넓혀도 해당 시간 기준 안에 관련 뉴스가 전혀 없으면, 그때만 해당 항목/하위그룹에 "특이사항 없음"이라고 짧게 쓴다.
- 새 소식이 있으면 항목당 **3~5줄** 요약.
- 각 요약 항목에는 아래 정보를 가능한 한 구체적으로 포함:
  - **수치**: 몇 MW/GW급인지, 몇 달러/원 규모인지
  - **전력원 종류**: LNG, 원전, 재생에너지(태양광/풍력), ESS, 수소/SOFC 등
  - **발전 vs 송전 구분**: 새 발전설비를 짓는 것인지, 기존 송전망/변전소를 연결하는 것인지 명확히 구분
  - **계획/일정**: 몇 단계, 언제까지, 어떤 절차인지
  - (금융조달 항목 한정) **조달 규모**, **조달 방식**(회사채/PF/사모대출/증자/전환사채 등), **투자자·주간사**
- 각 요약 아래에 **이해하기 쉬운 시사점 1~2줄** 추가 (예: "~라는 의미", "~에 우호적인 신호" 등 평이한 설명).
- 각 요약에는 **출처 링크**(기사 제목 + URL)를 반드시 남긴다. 링크 없는 내용은 포함하지 않는다.
- 저작권 보호를 위해 기사 문장을 그대로 인용하지 않고 반드시 자신의 말로 paraphrase한다 (직접 인용은 15단어 미만, 출처당 최대 1회).

## 출력 형식 (중요)

- 결과는 **채팅에 텍스트로 나열하지 않고, 깔끔한 HTML 파일로 출력**한다.
- 파일 최상단에는 반드시 **"조사 날짜: YYYY년 M월 D일"** (검색을 수행한 실제 오늘 날짜 — 반드시 그날의 실제 날짜를 다시 확인할 것, 이전 실행 날짜를 재사용하지 않는다)을 표시한다.
- HTML은 `/mnt/user-data/outputs/esmi_briefing_YYYYMMDD.html` 로 저장하고, 완성 후 `present_files`로 사용자에게 전달한다.
- 별도의 설명 텍스트(예: "브리핑을 준비했습니다" 같은 서두)는 붙이지 않고, HTML 파일만 바로 제공한다. 파일 공유 후 군더더기 후기 문구도 붙이지 않는다.

### 이메일 호환 필수 규칙 (중요 — 반드시 준수)

이 HTML은 브라우저뿐 아니라 **Outlook/Gmail/Naver 메일 등 이메일 클라이언트에 그대로 복사해 붙여넣어도 깨지지 않아야 한다.** 이메일 클라이언트는 `<style>` 블록, CSS 변수, flexbox/grid를 무시하거나 잘못 렌더링하는 경우가 많으므로, 다음을 예외 없이 지킨다:

- **표(table) 기반 레이아웃만 사용한다.** `<div>` + flexbox/grid 레이아웃 금지. 전체 문서를 폭 600px짜리 마스터 테이블 하나 안에 헤더/섹션/여백행을 순서대로 쌓는 구조(`<table role="presentation" width="600" style="width:100%;max-width:600px;">`)로 작성한다. 반응형을 위해 각 셀에 `width="100%" style="max-width:600px"`를 병행하되 미디어쿼리에는 의존하지 않는다.
- **모든 스타일은 각 태그의 `style=""` 속성에 직접 인라인으로 작성한다.** `<style>` 블록에만 규칙을 적어두고 클래스로 참조하는 방식은 금지 (이메일 클라이언트가 `<style>` 블록/클래스를 제거하면 스타일이 통째로 사라짐).
- **CSS 변수(`var(--x)`)를 사용하지 않는다.** 색상은 항상 16진수 값을 각 요소에 직접 적는다.
- **flexbox/grid, `gap` 속성을 사용하지 않는다.** 배지(badge)처럼 가로로 나열되는 요소는 작은 `<table>`의 각 `<td>`로 구현한다.
- **시사점(insight) 박스**는 `border-left` 대신 2칸짜리 표(좌측 3px 색상 셀 + 우측 텍스트 셀)로 구현한다.
- **폰트는 웹세이프 폰트만 사용한다**: `Arial, Helvetica, sans-serif`. 커스텀 시스템 폰트(-apple-system 등)에 의존하지 않는다.
- `border-radius`, `box-shadow`는 보조적 장식으로만 사용하고(구형 Outlook에서는 무시되어 각진 사각형으로 표시됨), 레이아웃이나 가독성이 이 효과에 의존하지 않도록 한다.
- 디자인 가이드: `assets/template.html`을 그대로 구조적 기준으로 삼는다. 다음을 지킨다:
  - 상단 헤더 셀(어두운 배경)에 타이틀 "ESMI · Energy Solution Market Info"와 조사 날짜
  - 7개 항목을 각각 흰 배경 표 셀로 구분하되 **원문자 번호는 사용하지 않고 굵은 제목 텍스트만** 사용한다. "항목 정렬 규칙"에 따라 뉴스 있는 항목을 위로, "특이사항 없음" 항목을 아래로 배치한다.
  - "국내 반도체 관련 전력/발전 업체" 항목은 용인/평택/호남권/기타 4개 하위 표로 재구분하며, 하위 표 제목에는 회사명 등을 괄호로 덧붙이지 않고 지역명만 쓴다. 이 하위 표들도 동일하게 내용 있는 것을 위로 정렬한다.
  - 수치(MW/GW), 전력원, 발전/송전 구분은 작은 표 형태의 배지(badge)로 표시
  - 금융조달 항목은 조달 규모($/원)와 조달 방식(회사채/PF/사모대출/증자 등)을 별도 색상의 금융용 배지로 표시하되, **다른 항목들과 동일하게 날짜 배지(M/D)도 빠짐없이 함께 표시**한다
  - Time-to-Power 항목은 왕복동엔진/소형·Aero가스터빈 하위 표로 구분하고, 맨 아래에 **"SOFC 대비 비교 인사이트"** 소제목의 요약 박스(시사점 박스와 동일한 2칸 표 스타일이되 보라색 톤)를 별도로 둔다
  - 시사점은 2칸 표(좌측 색상 강조 셀)로 표시
  - 출처 링크는 각 항목 하단에 리스트로 정리, `target="_blank"` (이메일에서는 무시되어도 무해함)
  - "특이사항 없음" 항목은 톤 다운된 회색 배경 셀로 표시
  - 전체적으로 여백이 넉넉하고 모바일에서도 읽기 편한 구조

## 실행 순서

1. 오늘의 실제 날짜를 다시 확인한다 (이전 실행에서 사용한 날짜를 그대로 재사용하지 않는다).
2. 사용자가 특정 URL을 제공했다면 먼저 `web_fetch`로 모두 확인
3. 7개 항목에 대해 웹 검색한다. "검색 깊이 규칙"에 따라 항목당 최소 2~4회, 구체적 수치·기업명이 나올 때까지 반복 검색하고 가능하면 출처 2개 이상을 확보한다 (SOFC·PAFC업체/데이터센터는 국내+해외 기사 균형 있게, 반도체 전력/발전 업체는 용인/평택/호남/기타 각각 검색하되 전력 기술 뉴스로 좁히지 않고 노동·재정·통상 이슈까지 확장, 국내 발전사 동향은 KEPCO·발전공기업·민간발전사 중심으로 전력·송전·변전·발전 전반의 이슈·정책·정치 뉴스를 폭넓게 검색, 데이터센터는 "데이터센터" 단어에 의존하지 않고 전력·기업·펀드 동향으로 폭넓게 검색, 금융조달은 데이터센터·SOFC 금융조달 뉴스 별도 검색, Time-to-Power는 미국/한국/일본/유럽 왕복동엔진·소형·Aero가스터빈 워치리스트 기업을 검색하고 마지막에 SOFC 대비 비교 인사이트 작성)
4. 사용자가 특정 기간(예: "8/28~31")을 지정하면 그 기간을 기준으로, 지정이 없으면 "검색 기준 시간" 규칙(오늘이 월요일이 아니면 24시간, 월요일이면 72시간)에 맞는 뉴스만 선별. 뉴스가 없으면 "특이사항 없음" 처리 (단, 사용자가 직접 제공한 URL은 시점과 무관하게 포함)
5. "항목 정렬 규칙"에 따라 뉴스 있는 항목/하위그룹을 위로, "특이사항 없음"을 아래로 재배열
6. `assets/template.html` 구조(표 기반 + 인라인 스타일, 이메일 호환, 번호 없는 제목, 지역명만 있는 하위그룹 제목)를 그대로 따라 최종 HTML 작성 (조사 날짜 최상단 포함)
7. `/mnt/user-data/outputs/`에 저장 후 `present_files`로 전달, 추가 설명 없이 종료
